## Scope, actions and endpoints

New namespace `/api/catalog-disposition/receipts/:id` where id is actual warehouse receipt UUID. Scoped GET detail, `/inspections`, `/inspections/:revision`, `/events`, `/stock-movements`. List endpoints default25/max100 UUID cursor ascending, `{data,page:{limit,nextCursor}}`; inspection list omits content. Detail/history reads require `catalog.qc.read`. Mutations: POST `/inspections` needs `catalog.qc.record`; POST `/approve` needs `catalog.qc.approve`; POST `/putaway` needs `catalog.putaway`. Dedicated roles catalogQCReader/Recorder/Approver/catalogPutaway each include qc.read plus action; owner gets all. No implicit old procurement/warehouse grants. Owner may record and approve; separate actions are not a two-person guarantee. Source selection/navigation still uses existing catalog.read/master.read.

Every mutation body includes expectedVersion (disposition head public version), expectedReceiptVersion (actual physical receipt.version), reason trimmed3..500, idempotencyKey `[A-Za-z0-9_-]{8,100}`. Virtual unrecorded head version1/currentRevision0 does not write on GET; first inspection expects1 and creates headversion2. Every successful fresh mutation increments both head and actual receipt version via exact CAS; concurrent hold/release competes on receipt. Actual committing authorization occurs before durable replay; exact replay returns original view and makes no fresh dependency/stock effects. Different payload/key reuse409 IDEMPOTENCY_CONFLICT.

POST `/inspections` additionally `{acceptedQuantity:"1.25",rejectedQuantity:"0.25",evidence:"Actual operator inspection"}`. LOT quantities nonnegative canonical decimal strings <=18 integer/6fraction digits, exact accepted+rejected=original received. LOT rejects any acceptedSerials/rejectedSerials field. SERIAL additionally requires BOTH explicit arrays acceptedSerials/rejectedSerials, disjoint/unique/exhaustive union of original real serial IDs; array counts equal corresponding exact quantities, <=100 source identities. Empty arrays/zero partitions allowed, never invented IDs. Evidence trimmed3..2000. Fresh inspection may record historical evidence under hold or later master drift. Only UNRECORDED/DRAFT may record, max100 immutable full revisions; no record after approval.

POST `/approve` adds `revision` equal current DRAFT revision. Requires exact current APPROVED PURCHASED master revision/version/hash/owner, active selected plant/entity, strict authoritative holds (including present non-null malformed cache even active:false), and receipt real write. Immutable inspection remains unchanged. Approval terminally binds revision/hash/partition/actor/time; no supersession or correction endpoint. Rejected quantity remains quarantined permanently within this scope, no available/reusable stock, no PO entitlement reversal.

POST `/putaway` adds `{locationId:"UUID",expectedLocationVersion:2}`. Only APPROVED with acceptedQuantity>0, once, whole accepted amount server-derived; no caller quantity/serial partition. Requires current exact source master approval and strict receipt holds; real current QUALIFIED company location same derived owner, exact expected public location version, valid immutable location authority and unchanged active real bin snapshot. Real item/location/raw-bin use-fences plus receipt/head/balance/unit CAS serialize withdrawals/holds/concurrent putaway. All-reject approval is terminal CATALOG_REJECTED; putaway409 CATALOG_DISPOSITION_STATE_CONFLICT, no zero movement/balance availability.
