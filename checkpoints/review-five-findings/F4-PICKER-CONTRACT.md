# F4 source selector query contract

Frozen wire, 2026-10-25. Source baseline54a7e6d; implementation/tests require current verification.

GET `/api/catalog-procurement/options/items?eligibility=PURCHASED_V2_APPROVED&q=&limit=25&cursor=<lastUUID>` and `/options/vendors?eligibility=ACTIVE_VENDOR&q=&limit=25&cursor=<lastUUID>`. Limit1..100, default25. q trimmed prefix max80 characters, matched literally after JavaScript lowercase normalization; no regular-expression or Mongo operators accepted. Unknown query fields rejected. Items match code or description prefix case-insensitively; vendors match name prefix. Scope derives from authenticated selected tenant/plant. Item eligibility additionally requires current owner, APPROVED PURCHASED V2 LOT/SERIAL; every returned item validates immutable current master authority. Vendor eligibility requires active absent (legacy) or exactly true; exactly false is ineligible, any other present value is corrupted source authority. This is not a vendor approval/provider verification lifecycle.

Requires catalog.read plus master.read for items or procurement.read for vendors. Existing dedicated permissions remain meaningful. Response `{data:[options],page:{limit,nextCursor},query:{q,eligibility,ordering:"_id_asc",consistency:"LIVE"}}`. Item `{_id,code,content,currentRevision,version,ownerLegalEntityId,eligible,blockers}`; vendor `{_id,name,version,eligible,blockers}`. Eligible search results have eligible:true. Direct GET `/options/items/:id` and `/options/vendors/:id` returns `{data:option}` and can return eligible:false with explicit blockers; corrupted authority fails closed instead of being mislabeled ineligible. Foreign scope/owner404. Existing captured revision/version remains separate from current hydration; the UI must not silently replace a saved selection.

Ordering uses globally unique UUID _id ascending, so its own tie-breaker is deterministic. On a stable dataset each page advances with _id > cursor without omissions or duplicates. Pagination is live across requests; inserts below the current cursor or eligibility changes require refresh from the first page. Changing q/eligibility resets pagination. UI cancels or ignores old responses and preserves selected IDs independently of active result pages.

The technical `catalogOptionSearch` collection stores one source-bound projection per item/vendor: source UUID `_id`, tenantId, plantId, type, ownerLegalEntityId (null for vendor), eligible, prefixes, sourceVersion and sourceAuthorityHash. Prefixes contain empty string plus each lowercase literal prefix of code/description or vendor name, capped at80 UTF-16 code units per field, at most161 unique tokens per item or81 per vendor. Named multikey index `catalog_option_prefixes` on tenantId/plantId/type/ownerLegalEntityId/eligible/prefixes/_id supports exact prefix-token equality and UUID cursor ordering. Candidate rows are reloaded from the actual source and compared to a fully recomputed projection, then validated against current immutable master/source authority. Cache data cannot authorize a procurement mutation.

Item create/revise/approve/deactivate and vendor create maintain source and projection in the same existing authorized transaction. Startup before HTTP serving rebuilds existing rows in batches of100, using a fresh snapshot and source version/authorityHash CAS plus real item useFence or vendor catalogSearchFence; concurrent compatible source writers refresh the same projection atomically. Concurrent inserts behind a bootstrap cursor already have a projection from their source transaction. Startup aborts on an unrecoverable source fence conflict rather than serving a partial rebuild. No existing immutable master revision/event is rewritten.

Capture actual executionStats on250 sources for empty/common/rare/no-match prefixes. Owner assertions require no-match zero documents and at most1 examined key, rare match one document and at most2 keys. The previous source-scope residual-query result (250 documents for a miss) proves pagination only and is superseded for search performance acceptance. These budgets concern the candidate lookup, with at most limit+1 actual candidate source reads, not total database capacity. Current source hydration and mutations revalidate independently.

Cache completeness is maintained by these supported transactions and startup rebuild. Arbitrary privileged deletion of a projection while serving can hide a source from search until rebuild; exact ID hydration still resolves the actual source and mutation authority stays intact. This technical cache is not an independently tamper-proof inventory authority, and no such claim is made.

Fresh typed request create/revise, approval, conversion, PO issue and receipt each reload the actual scoped vendor: active absent/true is valid, false rejects409 VENDOR_INACTIVE, malformed present active or invalid name/version rejects409 CATALOG_SOURCE_INVALID. These commands CAS-write the vendor's existing version/name/activation predicate with a hidden catalogUseFence, competing with any real vendor withdrawal without changing vendor business version. Historical source reads remain valid after later inactivity and show live VENDOR_INACTIVE blockers; committed exact replay still checks fresh authorization first and returns the original acknowledged result without reinterpreting later vendor eligibility. No vendor-deactivation API or provider verification lifecycle is introduced.
