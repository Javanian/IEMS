## Source and stock authority

Existing immutable QC/putaway opening balances/units/events remain unchanged. New catalog stock-use authority binds exact originHash, opening balanceHash and accepted opening units. Current view separates accepted opening, rejected quarantine, physical onHand, reserved, issued, consumed and available. onHand=accepted-consumed; available=accepted-reserved-issued-consumed. Releasing an unissued reservation restores availability but never erases history. ISSUE moves reserved to issued with no second physical decrement; first actual production record consumes those exact issued inputs once. Units project AVAILABLE/RESERVED/ISSUED/CONSUMED, independently of immutable opening disposition; rejected units never enter eligible stock. Holds or current item/location withdrawal make eligible quantity0 without changing physical ledger. No legacy writer can use this authority.

Every source write uses real receipt version CAS plus catalogUseHead CAS; every selected serial binds its global registry/opening unit with current use state. Source master and opening location/bin use fences compete with deactivation/withdrawal. All fresh reserve/release-production/issue/first-consume/QC require current exact source item/owner/location and authoritative strict holds. Historical attribution remains recordable under later holds; unissued reservation abandonment is allowed under hold/drift with valid stored authority. Source revision snapshots are locked at reservation and issue, cannot silently rebind. All state, reservation versions, issue/consume ledgers, audit/outbox/key commit atomically after committing authorization. Guard precedes replay; exact replay returns original acknowledged result.

## Reserve, issue and execute

POST `/orders/:id/reservations` adds `{materialLineId,receiptId,expectedReceiptVersion,expectedStockVersion,quantity,serials?}`. PLANNED only, actual stored eligible receipt matches exact approved material item/revision/UOM/owner. LOT exact positive quantity, no serials field. SERIAL explicit unique accepted AVAILABLE source serials with integral matching quantity. Reserve cannot exceed line demand or current stock. At most20 source receipts/reservations per execution and100 input serials total; a source receipt appears once per execution. POST `/reservations/:reservationId/release` plus expectedReceiptVersion/expectedStockVersion marks full reservation RELEASED before production release only; no physical return command. No generated incoming IDs.

POST `/orders/:id/release` common only requires exact full reservation for every material demand and freezes release snapshot, PLANNED->RELEASED. POST `/issue` common only revalidates actual sources and exact reserved claims, writes actual immutable issue per source, moves claim states ISSUED. No stock is consumed yet. Issue is whole released demand once.

POST `/records` adds `{operationIndex,inputQuantity,goodQuantity,scrapQuantity,laborMinutes,machineMinutes,evidence,outputSerials?}`. Operations must match frozen approved routing in order; exact nonnegative good+scrap=input and input=priorgood/initialtarget. Minutes are exact nonnegative decimal strings max6fraction, operator-recorded effort, not hardware telemetry or payroll. First record consumes exact issued material once with immutable consumption ledger and source fences. Later operation records do not consume material again. Final operation requires exact unique actual outputSerials count=good integral<=100, claims global warehouseSerials `{sourceType:"INTERNAL_OUTPUT",internalExecutionId,unitId}` and creates real internalOutputUnits QUARANTINED. No output serial supplied to nonfinal operation. Zero-good final permits explicit empty serial list and all consumed material must later be recorded as loss.

## Provenance, output quality and company stock

POST `/allocations` adds `{outputUnitId,sources:[{receiptId,quantity,serials?}]}`; full draft attribution for one actual output, max20sources, exact aggregate amount per MATERIAL LINE across all source receipts not above its frozen quantityPerUnit and consumed budget. SERIAL quantities match distinct actual consumed input identities. An identity belongs to at most one output or process loss; no manufactured child graph implied. POST `/losses` adds `{sources:[...]}` full draft process-loss attribution. They are historical evidence commands in QUARANTINED phase, allowed while held, never stock release/reuse. Full revisions/events remain immutable; no correction after output QC.

POST `/qc` adds `{acceptedSerials:[],rejectedSerials:[],evidence}`. Exact disjoint exhaustive actual output partition; requires each good output to receive exactly quantityPerUnit for EVERY material line summed across all selected source receipts, plus complete per-receipt and per-line process-loss reconciliation against every actual consumed receipt/identity. Per-line loss must equal consumed line demand minus final-good output count times its ratio; globally balanced but uneven per-output mapping is rejected, current source holds/master/location and current output master. All accepted and rejected output identities retain origin and operator QC evidence. Terminal quality disposition; no rework contract in this supplemental increment. Empty partitions valid where no good outputs. Output rejected quarantine never becomes available.

POST `/putaway` adds `{locationId,expectedLocationVersion}`. Whole positive accepted output once to current owned QUALIFIED location/realbin. Creates actual separate internalCompanyStockReceipts bound produced output IDs/current immutable execution+QC/provenance and typed output stock units. It is NOT a fabricated warehouse purchase receipt. Company output inventory UNVALUED; no allocation of manufactured children, financial posting or second raw-material consumption. All-reject/zero-good has no positive company receipt/putaway. Manufactured graph/cycles/descendantfreeze/rework/spares remain explicit later gates.
