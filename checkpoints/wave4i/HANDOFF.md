POST /api/commercial/inquiries {accountId,lines,idempotencyKey} -> 201 `{data:inquiry}`; omit lineId at creation. POST /:id/stage {expectedVersion,toStage,reason,idempotencyKey} -> 200 `{data:inquiry}`; DRAFT -> SUBMITTED -> IN_REVIEW only. GET collection/detail as above.

POST /:id/convert {expectedVersion,revision,expiresAt,taxPolicy,roundingPolicy,prices:[{inquiryLineId,unitPrice,currency}],idempotencyKey} -> 200 `{data:{inquiryId,inquiryRevision,quoteId,quote,lineMapping:[{inquiryLineId,quoteLineIndex}]}}`. Prices cover each source line once. Quote full stored record uses existing commercial routes thereafter. Inquiry becomes QUOTED. All mutation keys durable and scoped; exact replay returns stored response, changed payload/key reuse 409. Stale version/state 409, invalid inquiry payload 422, forbidden 403 or concealed foreign resource 404.

Quote revision lines add `provenance:{inquiryId,inquiryRevision,inquiryLineId,itemCode,drawingNumber,drawingRevision}`; commercial revision requests retain identical provenance plus original description/quantity/uom and line order, changing only prices/currency/policies/expiry. Approval and SO snapshot retain provenance. Shipment and invoice lines expose server-derived `provenance`. Direct legacy quotes remain supported.
