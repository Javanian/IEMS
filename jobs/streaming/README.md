# Event-time telemetry projection

PyFlink 1.20 adapter `attach(env, source)` accepts a Kafka string DataStream; integration supplies authenticated source, durable checkpoint storage, and transactional/version-fenced sink. Restart from completed checkpoints with stable operator UID. EXACTLY_ONCE here covers operator state; do not claim end-to-end exactly once without a transactional sink. Route kind=quarantine to retained correction evidence, never trusted risk metrics. No business ledger writes.

Contract: type telemetry.snapshot, payload resourceType telemetry, value decimal string <=12 decimal places, abs<=10^12, uom and deleted boolean. Per sample aggregate versions begin at 1. A sample's occurredAt/window/UOM is immutable across correction versions; moving a sample requires a tombstone in the original stream and a new sample ID. Events must be keyed to the same tenant/plant/UOM/window. Full snapshots correct the prior contribution. One-minute windows, 30s out-of-order watermark, five-minute allowed corrections. Emit increasing window revisions after close and after each correction; sink upsert uses full key+revision. Beyond-lateness records require bounded batch correction. No fabricated health/risk score is inferred from telemetry.

State per window capped at 5000 samples and 20000 receipts, cleared at window end+lateness. Version gaps, changed duplicate content and capacity overflow fail job for replay/repartition. A global source/partition cardinality quota and idle handling must bound concurrent keys in deployment. Final QA must prove timer behavior, restart and sink fencing with real Flink; adapter syntax does not establish those results.
# Stream separation after reporting v2

Financial full snapshots use iems.reporting.snapshots.v2 and never enter the telemetry operator. Telemetry retains its existing explicit sample schema/event-time/UOM contract and separate routing; generic source metadata is not a financial snapshot. Shared events.validate recognizes both existing v1 raw events and strictly validated reporting v2. No telemetry emitter adoption or live Flink/checkpoint acceptance is claimed by the v2 source adapter. Independent runtime QA remains at program end.
