# Iceberg/PySpark backfill

Run `backfill(spark, catalog.namespace.table, ordered_manifests, receipt_path)` in a serialized owned Spark session configured with Iceberg extensions/catalog and a dedicated lake warehouse. Source manifests and checksums are verified before each write. Data retains envelopes, tombstones, receipt/availability times, exact decimal strings and source IDs. One driver batch <=10000 records; run <=100 manifests/one million events; four shuffle partitions. Operator must bound executor/driver memory and admission concurrency; no local runtime is launched automatically.

MERGE inserts only missing event IDs; existing different checksums fail. Retries after uncertain commits use the same input and receipt identity, never append blindly. Every batch reconciles sink rows and duplicates. Receipt records source head hashes and actual Iceberg snapshot ID only after parity. A failed run can have committed partial batches, but has no new trusted receipt; resume same inputs to complete. Downstream publication must require the reconciled receipt. One writer per table is mandatory because Iceberg does not enforce unique constraints. Concurrent writers need an external serialized job fence, supplied by platform integration.

`compact` rewrites only an explicit UUID tenant/plant partition with one file group at a time; obtain an owned job lease first. Keep snapshots and source files; no expire_snapshots/remove_orphan_files is authorized here. Pin/read the receipt snapshot for reproducible reporting and compare event counts/hash sets with raw and dbt before trusted publication. Snapshot rollback is a projection operational decision, never a source rollback. Real Spark/Iceberg crash/compaction/parity QA NOT_RUN until final QA environment is available. Databricks and cloud warehouse delivery remain optional/external and are not claimed.
