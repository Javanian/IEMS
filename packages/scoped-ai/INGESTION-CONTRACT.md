# Document ingestion and retrieval — PLAT-027

Sources are manual plain text (`MANUAL_TEXT`) or current approved LEGACY/CATALOG purchase order extraction (`COMMERCIAL_APPROVED_REVISION`). No URL fetching, remote file execution, hidden personal history, synthetic production text or fabricated model response exists. PDF/OCR and other issued document formats are unsupported; the supported business artifact is the approved PO projection.

`createAiDocuments` provides the concrete authoritative source adapter for the scoped index. Ingestion publishes a UUID document, title, deterministic plain-text chunks and an explicit per-user ACL. Each reader must have an active user and tenant membership covering the selected plant/legal entity; user and membership writes fence concurrent revocation. No membership or foundation role is granted. All changes use foundation command authorization/replay, expected revisions, atomic result/audit/outbox and bounded transaction handling. Changes increment content/ACL revisions; previous index generations abstain until rebuilt. Revocation makes source reads fail immediately even if Qdrant is unavailable. This collection is a document store, not a financial/domain ledger.

Source reads verify current tenant, plant, legal entity, per-user ACL, active status and content hash and fence the same document in the retrieval transaction. Approved PO ingestion takes sourceReference `{cohort,vendorId,orderId,documentRevision,sourceHash}` instead of operator text. It uses the existing approved PO reader under dedicated internal `ai.vendor.source.read` permission, fences the original header, derives title/text from whitelisted facts and preserves decimal strings and original hash. No cohort fallback, mutable promise-as-revision or copied business authority is used. Every retrieval passes the opaque scope and rechecks current business permission, revision/hash, original content and per-user document ACL. A superseded/revoked source fails closed, including source-bound publish replay. Listing also rechecks business authority. `aiIssuedDocumentReader`/`aiIssuedDocumentAdmin` are opt-in explicit role definitions; no user or grant is provisioned.

The installer in `apps/portfolio-api/src/rag.mjs` exports `ragRoles`, `createRagRuntime(runtime, {embeddings, vectors})`, and `installRag(app, rag)`. CTO TPR-149 owns registration in the authenticated app, role map, shared routes/manifest, body size limit (at least 110 KiB, hard capped) and lifecycle. The installer expects the existing authenticated `req.scope`, performs selected-scope alias checks, rejects unknown mutation fields, validates resource UUIDs and emits `Cache-Control: no-store`.

Endpoints:

- GET `/api/ai/documents`: current reader-visible metadata, capped at 50, honest coverage.
- PUT `/api/ai/documents/:id` or POST `/api/ai/documents/:id/publish`: `{key, expectedRevision, title, text?, sourceReference?, allowedUserIds}`; revision 0 creates, subsequent CAS replaces. SourceReference derives its own title/text and ignores manual text. Without it, manual text is required.
- POST `/api/ai/documents/:id/revoke`: `{key, expectedRevision}`; revokes authoritative source and ACL.
- POST `/api/ai/documents/:id/rebuild`: `{key, expectedRevision}`; expected **index** revision, distinct from document revision.
- POST `/api/ai/retrieve`: `{query, limit?}`; revision/ACL checked evidence, never an asserted live order state.

Provider configuration is optional for document persistence. Retrieval/rebuild return `AI_PROVIDER_UNAVAILABLE` 503 until explicitly authorized embedding/vector adapters are supplied. No model access, results, enrollment or cloud acceptance is assumed. Underlying factory index initialization is explicit, not run in this implementation. AssistantWorkspace includes functional Documents and index controls: list, manual/approved publish, ACL replacement, source revoke, current status, model/source rebuild and index deactivation. Document revision and index revision are shown separately. Exact mutation commands are saved before POST in tenant/plant/user-scoped sessionStorage; ambiguity requires same-command reconciliation. Shared registration belongs to TPR-149, independent evaluation to final QA. The UI is not mounted by this branch.

Minimum evidence: source/ACL and indexing tests use in-memory database doubles plus real foundation command code; Qdrant transport tests use fetch responses. They do not prove Mongo transactions, concurrent revocation, actual provider results or HTTP/browser acceptance. Independent evaluations remain deferred to TPR-150/152 on the integrated candidate.
