# Domain events to reporting

Source authority remains MongoDB domain state. Use foundation `commands.execute` for domain/result/audit/outbox atomicity; do not call a broker inside the domain transaction. This package consumes that durable outbox. KafkaJS-compatible injected producer must use idempotent production configuration, TLS/auth and `acks=-1`. A lost publish marker can duplicate an envelope. Partition by tenant/plant/aggregate. Invalid schema stops publication without deleting source evidence.

Relay requires an explicit eventTypes allowlist and a single active publisher owner. Its kafkaPublishedAt marker is separate from publishedAt used by other transports (including platform Rabbit jobs); neither transport suppresses the other's delivery. Rows are sorted by aggregate revision, including same-millisecond commands. Integration must provision the scoped outbox routing/publication index before workload deployment, under its migration gate; no index is applied here. Route only mapped snapshot event types to reporting marts; retain unrelated domain events in their own raw stream without inventing snapshot fields.

Envelope v1: eventId/schemaVersion/tenantId/plantId/aggregateId/aggregateVersion/type/occurredAt/payload. IDs are UUIDs; timestamps UTC; decimal values strings with explicit currency/UOM. Payloads are full resource snapshots for analytics, with `deleted: true` tombstones, `resourceType`, and resource-specific fields. Unknown schema/type must quarantine, never infer domain meaning. Multiple events for one aggregate revision need distinct stream aggregates; the sequential consumer rejects ambiguous same-version events. Domain owners must explicitly map their events before enabling consumers.

Consumer authorization callback is mandatory. Mongo projection receipt, version head and effect share one transaction/session. Apply callbacks perform only Mongo writes using that session. Kafka offsets advance after commit. Revoke/deactivate producer scopes through authorization callback. Version gaps block and require source replay; no silent skip. Event ID reuse with changed content fails. Keep receipts for the replay horizon; deleting receipts requires an approved full rebuild.

Downstream raw files are immutable versioned envelopes plus receipt/availability timestamps, checksums and cursor ranges. Publication requires reconciled manifests and successful quality gates. Reporting is read only, never a writable business ledger. No SAP posting, source mutation, production migrations or cloud acceptance are included.

Integration owner supplies Kafka client lifecycle, source type mapping, service authorization and foundation runtime wiring. No root manifest/router change is made here. Minimum syntax is separate from final independent broker/restart/reconciliation QA.

## Actual-source adapter and private integration

`createReportingSource({db,client,foundation,authorizeResource})` in apps/portfolio-api/src/reporting-source.mjs is a service library. There is no public ingestion route. Initialize helper and adapter indexes through CTO-owned lifecycle before invocation. Resource authorizer is mandatory and must enforce source record authorization/revocation in the supplied session; foundation independently reauthorizes quote.read or fulfillment.read for active scope. Required reads: salesOrders approved snapshot/account/quote references; fulfillmentKeys.result; fulfillmentAudit registered exact kind; fulfillmentInvoices account/currency/salesOrderId. No biometric, private message or arbitrary payload ingestion. Missing scope/version/financial proof throws and blocks publication. Every replay reauthorizes before receipt lookup.

`reconcile({scope,collection,after,limit})` reads at most 1000 source records plus one lookahead in one source-fenced snapshot transaction, writes parent snapshots first, and returns/persists a page manifest. Page coverage is always INCOMPLETE even on the last page: independently observed pages cannot prove one consistent whole scope. Mapping error aborts all page writes, preserves cursor, then persists a scoped quarantine reason in a new authorized transaction. Unknown commit outcome is reconciled with original keys, never quarantined as known failure. `reconcileScope({scope,limit})` scans orders and fulfillment receipts in the same transaction, bounded to 1000 combined records, validates every mapped resource and compares against stored reporting heads. Missing authority blocks rather than inventing a deletion. A successful manifest proves only this snapshot-time scope; it includes exact source hashes/high water and reporting event/hash/sequence heads. Larger scopes require bounded pages and a separately implemented source-wide fenced export; pages must never be promoted into a COMPLETE manifest.

Order source identity: collection=salesOrders, id=SO UUID, version=quoteRevision (approved immutable content version, not mutable SO version), hash=contentHash(JSON-compatible {snapshot,accountId,quoteId,quoteRevision}), eventKey=SO UUID. JSON-compatible dates are UTC strings. Amount=snapshot.total, currency=snapshot.currency, quantity sums exact same-UOM lines with sourceLineIndexes. Baseline observation is occurredAt; createdAt is sourceOccurredAt only. Live commercial MUST use this exact source key/hash and quantity grouping for bootstrap overlap dedup, baseline=false, and all original source event IDs gathered before one final-state append. Same source key/content returns the originally persisted baseline/live event unchanged.

Fulfillment identity: collection=fulfillmentKeys, id=result._id, version=result.version, hash=contentHash(JSON-compatible result), receiptId=fulfillmentKeys._id. Registered kind is validated through immutable fulfillmentAudit. shipment.recorded maps one shipment; payment.recorded resolves every allocation.invoiceId to its actual order and checks currency/account and sum allocations=payment.amount. invoice.issued is reference-only raw evidence and emits no reporting financial snapshot. Unknown kinds are unsupported/quarantined; aliases are not guessed. Current authority disallows unallocated amounts; inconsistent/unallocated evidence remains quarantined, never assigned to an order or line. A future explicit unallocated source requires its separate dataset/owner contract. Payment group UUID lives in reportingPaymentIdentities keyed tenantId/plantId/paymentId/orderId with unique index; live owners must reuse it in their transaction. Never randomly generate a new grouping UUID on replay.

Additional technical collections: reportingPaymentIdentities, reportingSourceCoverage, reportingSourceQuarantine. They contain projection identities/evidence, not a writable business ledger. No source records are edited. Integration delta: register the private source job with authorized resource checks, immutable coverage export, snapshot-only Kafka reader/relay, coverage consumer after snapshot replay, Python paths, schema migration provisioning and React route through existing allocated analytics gateway. These lifecycle/shared-route changes belong to TPR-149. Future producers TPR-140/141/143/144/145 adopt only their owned emitter files. Source reconciliation is usable independently of future emitters. Generic relay continues original outbox/topic behavior; v2 consumer rejects generic events and commits offsets only after atomic projection success.
