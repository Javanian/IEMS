# Domain events to reporting

Source authority remains MongoDB domain state. Use foundation `commands.execute` for domain/result/audit/outbox atomicity; do not call a broker inside the domain transaction. This package consumes that durable outbox. KafkaJS-compatible injected producer must use idempotent production configuration, TLS/auth and `acks=-1`. A lost publish marker can duplicate an envelope. Partition by tenant/plant/aggregate. Invalid schema stops publication without deleting source evidence.

Relay requires an explicit eventTypes allowlist and a single active publisher owner. Its kafkaPublishedAt marker is separate from publishedAt used by other transports (including platform Rabbit jobs); neither transport suppresses the other's delivery. Rows are sorted by aggregate revision, including same-millisecond commands. Integration must provision the scoped outbox routing/publication index before workload deployment, under its migration gate; no index is applied here. Route only mapped snapshot event types to reporting marts; retain unrelated domain events in their own raw stream without inventing snapshot fields.

Envelope v1: eventId/schemaVersion/tenantId/plantId/aggregateId/aggregateVersion/type/occurredAt/payload. IDs are UUIDs; timestamps UTC; decimal values strings with explicit currency/UOM. Payloads are full resource snapshots for analytics, with `deleted: true` tombstones, `resourceType`, and resource-specific fields. Unknown schema/type must quarantine, never infer domain meaning. Multiple events for one aggregate revision need distinct stream aggregates; the sequential consumer rejects ambiguous same-version events. Domain owners must explicitly map their events before enabling consumers.

Consumer authorization callback is mandatory. Mongo projection receipt, version head and effect share one transaction/session. Apply callbacks perform only Mongo writes using that session. Kafka offsets advance after commit. Revoke/deactivate producer scopes through authorization callback. Version gaps block and require source replay; no silent skip. Event ID reuse with changed content fails. Keep receipts for the replay horizon; deleting receipts requires an approved full rebuild.

Downstream raw files are immutable versioned envelopes plus receipt/availability timestamps, checksums and cursor ranges. Publication requires reconciled manifests and successful quality gates. Reporting is read only, never a writable business ledger. No SAP posting, source mutation, production migrations or cloud acceptance are included.

Integration owner supplies Kafka client lifecycle, source type mapping, service authorization and foundation runtime wiring. No root manifest/router change is made here. Minimum syntax is separate from final independent broker/restart/reconciliation QA.

## Actual-source adapter and private integration

`createReportingSource({db,client,foundation,authorizeResource})` in apps/portfolio-api/src/reporting-source.mjs is a service library. There is no public ingestion route. Initialize helper and adapter indexes through CTO-owned lifecycle before invocation. Resource authorizer is mandatory and must enforce source record authorization/revocation in the supplied session; foundation independently reauthorizes quote.read or fulfillment.read for active scope. Required reads: salesOrders approved snapshot/account/quote references; fulfillmentKeys.result; fulfillmentAudit registered exact kind; fulfillmentInvoices account/currency/salesOrderId. No biometric, private message or arbitrary payload ingestion. Missing scope/version/financial proof throws and blocks publication. Every replay reauthorizes before receipt lookup.

`reconcile({scope,collection,after,limit})` reads at most 1000 source records plus one lookahead in one source-fenced snapshot transaction, writes parent snapshots first, and returns/persists a page manifest. Page coverage is always INCOMPLETE even on the last page: independently observed pages cannot prove one consistent whole scope. Mapping error aborts all page writes, preserves cursor, then persists a scoped quarantine reason in a new authorized transaction. Unknown commit outcome is reconciled with original keys, never quarantined as known failure. `reconcileScope({scope,limit})` scans the registered source collections in one transaction, bounded to 1000 combined records, validates mapped resources and compares against stored reporting heads. Missing authority blocks rather than inventing a deletion. Its manifest includes exact source hashes/high water and reporting event/hash/sequence heads, but remains INCOMPLETE until whole-authority coverage is independently established. Larger scopes require bounded pages and a separately implemented source-wide fenced export; pages must never be promoted into a COMPLETE manifest.

Order source identity: collection=salesOrders, id=SO UUID, version=quoteRevision (approved immutable content version, not mutable SO version), hash=contentHash(JSON-compatible {snapshot,accountId,quoteId,quoteRevision}), eventKey=SO UUID. JSON-compatible dates are UTC strings. Amount=snapshot.total, currency=snapshot.currency, quantity sums exact same-UOM lines with sourceLineIndexes. Baseline observation is occurredAt; createdAt is sourceOccurredAt only. Live commercial MUST use this exact source key/hash and quantity grouping for bootstrap overlap dedup, baseline=false, and all original source event IDs gathered before one final-state append. Same source key/content returns the originally persisted baseline/live event unchanged.

Fulfillment identity: generic/manufactured collection=fulfillmentKeys, id=result._id, version=result.version, hash=contentHash(JSON-compatible result), receiptId=fulfillmentKeys._id. Registered kind and source event ID come from immutable fulfillmentAudit. Purchased identity uses collection=fulfillmentShipments, id=shipment._id, version=shipment.version, hash of shipmentSemantic (excludes document/delivery/return fences), and the actual SHIPMENT_POSTED purchasedFulfillmentEvents ID. Its purchasedFulfillmentKeys receipt must match shipmentHash, order and event commandProof.resultHash/key. Both identities exactly match appendFulfillmentReporting in fulfillment prerequisite 7f7ed96996e0d6a6955a5d0db2b93116f5b3d090. Source time is the immutable result shippedAt/createdAt, matching live emission; baseline occurredAt remains observation time. Replay preserves the original persisted event, including baseline and time.

shipment.recorded maps one shipment; generic WORK_ORDER/RESERVATION, purchased CATALOG_RESERVATION and manufactured COMPANY_OUTPUT are distinct registered cohorts. Every shipment must match its immutable result and source quantity/UOM. Typed cohorts additionally call the existing owner validatePurchasedShipment (delegates manufactured authority validation), in the same authorized transaction. Never reinterpret a typed source as generic or infer a shipment from metadata. payment.recorded resolves each allocation.invoiceId to its actual order and checks currency/account and sum allocations=payment.amount. It verifies the immutable payment result against fulfillmentPayments and existing purchased payment authority. CASH/DEPOSIT/CREDIT preserve live source settlementKind, cashEffect and balanceEffect metadata. Deposit application and credit require intact hash-checked fulfillmentDepositAllocations/fulfillmentCreditNotes; depositState verifies account-bound deposit conservation. Payment is receivable settlement, not necessarily a cash receipt. Payment group UUID lives in reportingPaymentIdentities keyed tenantId/plantId/paymentId/orderId with unique index; live owners reuse it in their transaction. Never randomly generate a new grouping UUID on replay or allocate payment to lines/UOM.

invoice.issued remains reference-only (no invoice dataset); parent orders are bootstrapped before children. deposit.recorded is validated with depositState and listed as unsupported account-unallocated evidence, never assigned to an order. packing.picked/packing.packed are explicitly non-financial unsupported evidence. ## Private runtime implementation return

`relayReportingSnapshots` now requires explicit `{tenantId,plantId,legalEntityId}` scope and `authorize(event)` on each delivery/replay. It resolves preceding aggregate versions and the actual order parent before children, independent of UUID sort or batch boundaries; missing dependencies block their markers. The original generic relay and its markers remain unchanged. One active publisher must use the private owner lifecycle, not independently call the relay from multiple loops.

`createReportingSource` additionally exposes `authorizeSnapshot({scope,event,session?})` and `extractCoverage({scope,runId,limit})`. Authorization verifies immutable outbox identity and reruns the registered source cohort/authority validators under current transaction authorization, including referenced parent/invoice/settlement resources. Explicit revoked/active/allowed-user restrictions and false authorizer results deny. Extraction validates immutable coverage hashes and bounded consecutive histories, retains exact event IDs/time, and remains INCOMPLETE/trustedZero=false. Missing historical authority cannot be substituted with mutable current data.

New reporting outbox rows and mapping receipts persist envelopeHash in their creation transaction. Delivery/replay rejects corrupt or unsealed evidence; no historical envelope is silently resealed from its present content. Existing unsealed persisted projection evidence needs an explicit source-backed validation/rebuild operation, not a production migration inferred from this code handoff. Domain authority remains intact and unchanged.

It is implemented as marker-owned LOCAL_FILE/SYNTHETIC with transactional Mongo projection/receipts, immutable extraction and optional existing Python raw API binding. Kafka and relational SQL runtime are explicitly unavailable/NOT_RUN in that composition; they need concrete private clients/effect wiring before activation.
