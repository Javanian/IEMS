# Reporting resource snapshots

Financial reporting consumes only `reporting.snapshot.v2`, schemaVersion=2, topic `iems.reporting.snapshots.v2`. Original v1 domain traffic remains separate raw evidence. Source revisions and original event IDs are provenance; reporting aggregateVersion is its separately persisted sequence. See packages/domain-events/READ-CONTRACT.md. Orders carry approved amount/currency once plus quantities grouped by UOM. Payments carry actual per-order invoice allocations without line allocation. Shipments carry actual quantity/UOM and source line reference. Each aggregate has complete consecutive versions starting at 1. Money and quantity are nonnegative decimal(38,12); excess precision fails. Corrections replace full snapshots; explicit tombstones retain full previous values and source reason. No automatic upgrade of metadata-only v1 events. Existing verified homogeneous v1 snapshots require an explicit isolated-epoch migration with lineage and a one-element quantities array; these consumers deliberately reject them until that operation is authorized.

Run `PYTHONPATH=jobs/analytics python jobs/analytics/marts.py candidate.duckdb <ordered manifest paths>`, then `dbt build --project-dir analytics/dbt --profiles-dir <private profile dir>`. Set IEMS_ANALYTICS_DB to the candidate path. Install requirements in an isolated tooling environment; dbt-duckdb is separately required. Never point this tooling at an application database. All manifest chains begin at cursor 0; an incremental load still validates the complete supplied chain. Interrupted loads roll back; unmanifested Parquet files are orphans and never trusted. Quarantine preserves rejected evidence and never advances a cursor. Raw source adapters checkpoint the opaque source cursor only after ingest returns a durable manifest; replay can create another batch but event IDs deduplicate at the sink.

SCD2 keeps event validity and receipt/availability time. Point-in-time queries must filter occurred_at <= business_as_of AND available_at <= knowledge_as_of and then choose highest aggregate_version within those bounds. Baselines claim no history before observation; original source time is provenance only. Do not use current_resources for historical decisions. Freshness uses actual availability and rejects empty/stale input. dbt contracts enforce chronology/version/relationships/currency/UOM/conservation. `order_balances` has one monetary row per order; `order_quantities` and `order_quantity_balances` contain units without money. The nested quantities array is a presentation shape, not repeated monetary records.

Coverage is separate from event freshness. `marts.load(...,coverage_manifests=[...])` verifies complete source manifests and matching immutable snapshot checksums. dbt coverage_status invalidates a manifest if current heads differ; coverage_complete blocks trusted publication. A missing amount always fails. No payment/fulfillment rows become zero only after complete reconciled coverage. Without it, relational reads expose INCOMPLETE and null financial/quantity balances. Coverage is as-of its observation, never a claim of live completeness. Airflow selection JSON is `{ "manifests":["raw/...manifest.json"], "coverage":["source/...coverage.json"] }`; paths must stay under the operator-owned input root. Old list selection is accepted but has no coverage and cannot publish trusted financial marts. Source adapter returns/persists the immutable manifest; integration must export it through an authorized private extraction job. PostgreSQL `Projection.apply_coverage(manifest)` is a private consumer operation, not an HTTP ingestion route.

Schema declaration 001_projection.sql now describes a fresh isolated v2 projection. It has NOT been run. Existing v1 projection instances must rebuild in an explicitly isolated epoch under separately approved migration procedures; do not rerun CREATE TABLE or mutate a user DB. Projection receipts preserve full envelopes; order quantities have scoped FK/RLS. Source identities, receipt history and raw manifests must be retained for replay. Raw v2 manifest state is bounded to 100000 receipts; overflow stops ingestion before cursor publication and requires explicit partition/rebuild planning, never expiry.

DuckDB is a local single-writer file engine, not concurrent production BI serving. Serve governed snapshots via a dedicated reporting API/relational projection; production Redshift adapters need dialect compilation, permission and actual parity QA. DECIMAL(38,12), JSON extraction, timestamptz, QUALIFY/exclude behavior must be ported explicitly. Redshift/cloud acceptance is EXTERNAL_DEPENDENCY.
